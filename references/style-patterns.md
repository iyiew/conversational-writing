# 风格诊断

按当前草稿的问题选择相应维度检查，不要求每篇同时具备全部特征。短例用于说明表达方法，实际内容以用户材料为准。

| 维度        | 保留什么                     | 容易走偏的地方             |
| --------- | ------------------------ | ------------------- |
| 1. 说话者视角  | 用与任务相符的人称表达当时看到、做了和感受到的事 | 所有文体都强制第一人称，或使用全知口吻 |
| 2. 确定性    | 区分事实、感觉、猜测               | 每句都加“可能”，或把猜测写实     |
| 3. 自我修正   | 用户已经意识到的理解偏差，及仍成立的压力     | 为真诚感制造自责            |
| 4. 具体信息   | 对回忆或沟通有用的动作、时间、人物和数字     | 虚构精确数字，或堆无关生活细节     |
| 5. 普通事件   | 简单事情可以只记录、不分析            | 给吃饭、等待和休息都加意义       |
| 6. 现实约束   | 会改变判断的时间、资源、成本和条件        | 给简单事情补一套决策框架        |
| 7. 情绪转折   | 用户已有的触发事件及情绪强度           | 提升戏剧性，或淡化明确不满       |
| 8. 时间关系   | 日记保留真实顺序；消息可重点先行         | 按一个模板组织所有文体         |
| 9. 事件与理解  | 有需要时从具体事情走向解释            | 给没有原因的事情编因果         |
| 10. 多个因素  | 分清输入里互相牵制的条件             | 人为制造两面平衡            |
| 11. 他人观点  | 公平转述已有观点，再写自己的回应         | 代替对方猜动机或编对话         |
| 12. 口语连接  | 时间、转折和解释按语义自然衔接          | 每段“然后”，每句“其实”       |
| 13. 句段节奏  | 简单事实短写，复杂问题允许长解释         | 所有句子都碎，或整篇一大段       |
| 14. 程度表达  | 保留“很”“有点”“挺”等原有强度        | 把强硬拒绝改成犹豫建议         |
| 15. 专名与数字 | 保持实体、单位、期限和条件准确          | 为顺口改数字，或照搬示例专名      |
| 16. 自然停笔  | 记录结束即可结束                 | 自动追加感言和下一步          |
| 17. 暂时理解  | 复杂问题可以保持未解决              | 把痛苦改成积极成长           |
| 18. 已有行动  | 有计划才写计划，保留对象、时间和触发条件     | 从“想聊聊”补出议程或承诺       |

## 三种局部修正

确定性：输入“测试通过了，但还没确认能否周四上线”，可写“测试已经通过了，周四能不能上线还没确认。”不能写“周四就能上线”。

约束：输入“想把说明做详细一点，但页面只有一屏，先保留最常见的两个问题”，可写“我还是想解释清楚一点，不过页面只有一屏，所以先放最常见的两个问题。”不自动提出扩页或新增功能。

结构：两项待确认事项可以写成“想和你确认两件事：”加两条列表。口语表达与项目符号可以同时存在。
