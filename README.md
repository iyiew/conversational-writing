# 对话感写作

把想说的话写得自然、具体、有对话感，同时保留你的意思和必要的信息层级。

有时候内容已经想清楚了，写出来却太书面；有时候想让语气轻松一点，又担心改完丢了重点。对话感写作适合这类场景：给它一段草稿、几条笔记或明确的表达目的，它会帮你组织成自然、清楚的文字。

## 适合什么时候用

| 场景 | 可以帮你做什么 |
| --- | --- |
| 消息与回复 | 把重点说清楚，让语气符合沟通对象，保留明确的态度和请求 |
| 文案与说明 | 像和读者说话一样解释事情，让背景、条件和重点更容易理解 |
| 日记与个人记录 | 把零散笔记整理成连贯记录，保留具体细节和当时的感受 |

## 直接告诉它你想怎么写

把材料贴上，再加一句要求就可以：

- “帮我把这条消息写得自然一点，态度保持明确。”
- “这份说明保留小标题和列表，语气像在和团队说话。”
- “根据这些功能信息，写一段像在和读者聊天的介绍。”
- “把今天的几条笔记整理成日记，保留当时的感受。”
- “只调整措辞，人物、数字和信息顺序都保留。”

也可以补充收件人、希望的长度，或者你平时会用的表达。通常会直接得到成稿；需要多个版本时，可以要求“一个简短直接，一个温和一点”。

## 写得自然，也说得准确

它会保留具体事情、关键数字和影响判断的条件。确定的态度仍然明确，尚未确定的事情也会保留余地。句子可以简短，复杂的问题则留出解释的空间；普通事情说完就停，反思也可以停在当前的理解。

例如，一段草稿是：

> 资料已收齐，共 12 份，其中 2 份格式不一致。需要确认是否统一转换为 PDF，以及是否保留原文件。

可以整理成：

> 资料已经收齐了，一共 12 份。不过有 2 份格式不一致，想先确认两件事：
>
> - 要不要统一转成 PDF？
> - 原文件要不要保留？

## 小标题和列表可以保留

“自然一点”默认保留原稿中有用的小标题、列表、步骤和信息分组。短消息可以只有一两段，长说明可以用简短标题组织，多项待确认事项也可以分别列出。

如果你希望整篇连着说，可以直接要求“改成连续叙述”；整理日记时，也会按内容把零散笔记合成段落。

## 使用方式

从公开仓库获取完整技能：

```sh
git clone https://github.com/iyiew/conversational-writing.git
```

也可以在仓库页面通过 **Code → Download ZIP** 下载并解压，将文件夹命名为 `conversational-writing`。

通过所用 agent 的技能添加或导入入口加载完整的 `conversational-writing` 文件夹，然后提供写作材料与要求。

技能采用通用的 `SKILL.md` 与参考文件结构，写作规则适用于能够加载这类内容的 agent。Codex、Claude Code、DeepSeek Harness、Cursor、WorkBuddy、TRAE Work 的添加入口由各自客户端提供。

如果 agent 可以读取项目文件，也可以直接说：

> 读取 conversational-writing/SKILL.md，帮我把下面这段内容写得自然、有对话感，保留原意和小标题。
